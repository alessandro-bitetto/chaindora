## Detection and policy coverage

Version-specific synthetic incidents are detected, rendered to JSON and SARIF,
and produce exit 1 for npm package-lock v3, Yarn Classic/Berry, pnpm v9, Deno
v3/v5, requirements.txt, Poetry, uv, PDM, Pipfile.lock, NuGet, Paket, Go, Cargo,
Pyproject exact pins, and the .csproj fallback. An unmatched version produces
exit 0. Pyproject name-level wildcard matching also passes.

Operational inventory failures produce exit 2, regardless of suppressions,
severity choices or baseline-update requests. Gate process-control cases use
harmless manager doubles and assert that no final handoff occurs; these are
separate from the real-manager graph tests. The shell-based doubles run on
POSIX hosts; Windows CI runs the other 22 CLI contracts. The Deno stale-lock
subprocess unit test uses the Go test binary as a portable double.

The ordinary suite also covers inert credential-exfiltration signatures,
archive size/depth/truncation limits, registry failures returning Unknown,
mixed policy, cache revalidation, republish history and concurrent writes.
These are simulated evidence tests, not live malware tests. Bun inventory
remains outside documented parser coverage.

## Safety and reproduction

Generated package archives contain metadata and constant values. Python uses
wheels rather than source distributions. Go and Rust sources contain constants.
NuGet packages contain a nuspec and an empty library placeholder, without
assemblies or MSBuild targets. Fixture servers serve only generated content and
never proxy requests to public registries.

The separately enabled lifecycle fixture adds one harmless `postinstall` script:
write a constant string to `CHAINDORA_FIXTURE_SENTINEL`, a file in the disposable
test directory. It reads no credentials, starts no network request, and changes
nothing outside that directory. The provided runner enables this fixture only
in Node, Bun and Deno containers.

Tool preparation downloads official tools into Docker images. Real-manager test
containers then use `--network=none`, `--pull=never`, a read-only root, an
unprivileged user, no capabilities and `no-new-privileges`. Only test binaries
and the CLI script are mounted, read-only; no host home, credentials or Docker
socket is mounted. Temporary files disappear with the container. The separate
Linux ordinary-unit run mounts the checkout read-only and uses an image with
the project's Go dependencies already cached before networking is disabled.

Native macOS checks use temporary homes/caches and fixture registries; they are
not OS-sandboxed. Final native runs disable Corepack networking and use existing
manager entry points. Base image digests and top-level tool versions are pinned;
transitive tool dependencies are not fully locked. The runner records image IDs
and actual versions.

From the repository root, with Go, Python 3.9+ and Docker available:

```sh
# Network access is used only to prepare toolchains; tests are offline.
python3 tests/run_environments.py --prepare --output /tmp/chaindora-validation

# Reuse prepared images, without pulls.
python3 tests/run_environments.py --output /tmp/chaindora-validation-repeat

# Rerun only affected groups after a change.
python3 tests/run_environments.py --only node deno cli --output /tmp/chaindora-targeted

# Native CLI checks: inert manifests and doubles, no package installations.
go build -o /tmp/chdora-validation-cli ./cmd/chdora
python3 tests/offline_cli.py --binary /tmp/chdora-validation-cli --output /tmp/chaindora-cli-results

go test ./... -race -count=1
go vet ./...
```

The container runner stores logs, image IDs and `results.json`. Native CLI
validation also retains JSON stdout, stderr and SARIF per contract. See
[real-manager tests](../internal/gate/environment_integration_test.go),
[container runner](../tests/run_environments.py),
[CLI contracts](../tests/offline_cli.py), and
[CI workflow](../.github/workflows/test.yml).

Deno's no-`node_modules` restriction follows its documented lifecycle boundary:
[npm lifecycle scripts require a node_modules directory](https://docs.deno.com/runtime/reference/cli/install/).
Yarn Classic provides [script suppression](https://classic.yarnpkg.com/lang/en/docs/cli/install/);
Berry uses its own resolution mode with script execution disabled.

## Remaining boundaries

These fixes do not provide a process sandbox, complete command mediation, or
binding of the final install to inspected artifacts. The matrix is one small
dependency graph per manager; it does not cover all workspaces, private registries,
optional/peer combinations, Python markers, .NET targets, updates or tool versions.
Deno remains an existing-project resolver and Paket remains lockfile-only;
raw Deno HTTPS/JSR entries and Bun inventory remain outside declared coverage.

Real-manager execution on Windows and Linux amd64 remains pending. Windows
cross-compilation is not runtime validation. The new CI jobs are configured to
retain future runtime evidence; the passing rows above are not proof that
arbitrary packages are safe to install.
