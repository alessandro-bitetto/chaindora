## Purpose

`website/` is the chaindora.dev marketing landing page: a single-route Angular 18 standalone-component app that builds to a static bundle and is deployed independently of the `chdora` binary (Cloudflare via `wrangler.toml`, or any static host with SPA fallback).

## Surface

**Exposes** — a static browser bundle in `website/dist/browser/` (`index.html`, hashed JS/CSS, `assets/`). One client-side route `/`; every other path redirects to `/` and must be served by the host's SPA fallback. In-page anchors: `#prevention`, `#detection`, `#install`, `#fleet`, plus `#main` (skip-link target). Dev server via `ng serve` on port 4200 (Angular default; the `start` script sets no host, so it binds localhost by default). No backend API, no server-side code.

**Consumes** — no environment variables and no build-time configuration. Runtime browser calls: `GET https://api.github.com/repos/alessandro-bitetto/chaindora/releases/latest` (to display the current version; skeleton while pending, hard-coded `version` fallback on error or after 6s) and the Google Fonts stylesheet for Permanent Marker (linked from `index.html`; the page degrades to the system sans-serif if it fails). All links target `github.com/alessandro-bitetto/chaindora`. npm packages: `@angular/*` 18.2, `rxjs` 7.8, `zone.js` 0.14, `tslib`; devDependencies `@angular/cli`, `@angular-devkit/build-angular`, `@angular/compiler-cli`, `typescript`. Build needs Node.js and `npm ci` from `website/package-lock.json`.

## Behavior

- **Bootstrap**: `main.ts` boots `AppComponent` with `appConfig`; the router renders `HomeComponent` at `/`. Anchor links scroll within the single page via the router's `anchorScrolling`; because the router positions fragments with `window.scrollTo` (which ignores CSS `scroll-padding`), `app.config.ts` registers a `ViewportScroller` offset read live from the `cd-header` height so targets land below the sticky header on both desktop (72px) and phone (60px). `html { scroll-padding-top }` still covers native `scrollIntoView` paths.
- **Skip link**: the first tabbable element is `.skip-link` ("Skip to content"), visually hidden until keyboard focus, pointing at `#main`; `<main tabindex="-1">` receives focus so the next Tab lands on the hero Install button.
- **Header**: `HeaderComponent` is sticky via `:host { position: sticky }` (a sticky child cannot travel beyond the inline host box). It toggles `scrolled` from a `window:scroll` host listener and tracks the in-view section: on every scroll/resize/NavigationEnd, a rAF-coalesced `updateActive()` finds the anchored section (`prevention`, `detection`, `install`, `fleet`) straddling a reading line at header height + 30% viewport (max 240px); ties (side-by-side cards on desktop) resolve to the id in `location.hash`, else first in page order. The active link gets `.active` + `aria-current="true"` (red underline on desktop, red chip with dot in the mobile panel). The hamburger (≤720px) toggles a compact panel: 2×2 grid of section chips (1 column ≤380px) plus Threat model / GitHub; closes on link click, Escape, outside click, or resize past 720px. Its `aria-label` flips between "Open menu" and "Close menu"; `aria-expanded` is bound.
- **Version display**: `HomeComponent.ngOnInit` fetches the latest GitHub release tag over `HttpClient` with `timeout(6000)`. `versionState` starts at `loading` (hero chip, the two install-snippet `code-status` tags and the closing Download button render a `.skeleton` shimmer plus visually-hidden "Loading latest version" text, `aria-busy="true"`), becomes `live` with the tag (leading `v` stripped) or `fallback` (hard-coded `0.16.2`) on error/timeout. Skeletons never persist past 6s.
- **Install snippets**: kept as TypeScript string constants in the component because their shell `${…}` / `%{…}` braces would be parsed by Angular's control-flow template compiler. Both resolve the latest release at run time. The two binary snippets show a `latest vX.Y.Z` tag in the terminal title bar (hidden ≤560px). `copy(key, text)` writes via `navigator.clipboard` with an `execCommand('copy')` fallback; on success the pressed button turns red with a ✓ and reads "Copied", the surrounding `.code-block` gets `.flash` (red border + glow), and a `role="status"` polite live region announces "Copied <snippet name> to clipboard"; on failure the button reads "Failed" with ✕ and the region explains to copy manually. State resets after 2.2s. Each button has a static `aria-label` naming its snippet (`snippetNames`).
- **Layout system**: every landing section is `section.container.section` padded with `--cd-section-y`; `.section-shaded` paints a full-bleed grey band via a negative-margin pseudo-element (clipped by `html { overflow-x: hidden }`). Headings use fluid `clamp()` sizes. Mode cards, catches columns and roadmap phases use CSS subgrid, dropped when they stack (roadmap ≤900px, modes/catches ≤720px).
- **Accessibility system**: `:focus-visible` shows a 3px brand-red outline with a 5px white halo; inside `.on-dark`, `pre` and `.code-block` the ring inverts (white outline, red halo). Small red text on tinted surfaces (section eyebrows, hero version chip, active nav) uses `--cd-accent-ink` (#c62828, ≥4.9:1) while fills and display headings keep brand red #da2f2f; terminal comments are rgba(255,255,255,0.58) (≈6.6:1). `prefers-reduced-motion: reduce` zeroes animations/transitions, disables smooth scrolling and flattens the skeleton shimmer. Decorative legend dots and the mascot are `aria-hidden`.
- **Roadmap**: a static `roadmap` array of three phases (`now`, `next`, `later`) rendered by the template; edit the array, not the HTML.
- **Build**: `npm run build` → production configuration by default (`outputHashing: all`, budgets enforced), output in `website/dist/browser/`. `wrangler.toml` points Cloudflare at that directory with SPA not-found handling.

## Notes

- The website is **excluded from the repo's dogfood CI scan** (`chdora ci . --exclude website`) because Angular CLI build tooling carries its own CVE surface that does not ship with the `chdora` binary. Do not remove that exclusion without expecting new findings.
- **Inline component `styles:` are compiled as plain CSS** (no `inlineStyleLanguage` in `angular.json`): native CSS nesting works, but `//` line comments do not — use `/* */` in `header.component.ts`, `footer.component.ts` and `app.component.ts`; SCSS syntax is fine in the `.scss` files.
- **Never put `overflow-x: hidden` on `<body>`** — it makes body the scroll container for sticky descendants and the header silently stops sticking. The clip lives on `<html>` (propagates to the viewport) with `overflow-x: clip` on body as a non-scroll-container guard. Likewise keep `position: sticky` on the header `:host`, not only on the inner `.site-header`.
- The router's anchor offset in `app.config.ts` is what makes `#install`-style links land below the header; `scroll-padding-top` alone is not honoured by Angular's `window.scrollTo`-based anchor scrolling.
- `home.component.scss` is close to the 20kb component-style warning budget; keep dead CSS out of it and prefer global rules in `styles.scss` for anything shared (skeleton, skip link, focus rings live there for that reason).
- `pre` blocks rely on their top padding (≈38–40px) for the traffic-light chrome dots and the copy / status controls; do not reduce it in a media query.
- When testing with Playwright, dispatch clicks on header controls via `element.click()` in `page.evaluate` — Playwright's own `click()` scrolls a sticky element to its static position first, which resets the active section and produces misleading results. Smooth scrolling also needs generous waits or `scroll-behavior: auto` before screenshots.
- `package.json` lists `webpack`, `webpack-dev-server`, `ajv`, `picomatch`, `tmp` as runtime `dependencies` even though they are build-time; they exist to pin patched versions for the audit surface.
